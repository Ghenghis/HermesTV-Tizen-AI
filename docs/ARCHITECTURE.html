HermesTV - System Architecture

Single-page architectural reference for the HermesTV Tizen + Web TV app and its VPS backend. Captures the live state of main at the time this file was written. Use it to onboard, debug, or plan changes without re-reading the whole repo.

1. Public surface - Cloudflare to host nginx to containers

Production traffic for tv.daveai.tech (canonical; hermestv.daveai.tech kept as additive nginx alias) goes through Cloudflare in Flexible-TLS mode: the edge terminates HTTPS, the origin is HTTP. The Hostinger VPS runs a host-level nginx (not containerised) that owns ports 80/443 and reverse-proxies HermesTV's two private loopback ports to public hostnames. Caddy was originally planned in-stack but was removed in Phase 2 because the VPS already runs the host nginx for ten other daveai.tech sites.

Diagram 1 - public TLS path. The container ports are bound to 127.0.0.1 only; the public internet cannot reach them directly.

2. VPS docker stack (upstream/docker-vps/VPS_COMPOSE.yml)

All HermesTV containers share one private Docker bridge, hermestv-vps-internal. Admin UIs for IPTV tooling (Threadfin, m3u-editor, xtreamfilter) are unauthenticated by design, so after PR #39 each one is bound strictly to 127.0.0.1 - the operator reaches them via Tailscale or an SSH local-forward. State lives in named volumes prefixed hermestv-vps-.

Diagram 2 - VPS Docker stack. Solid arrows = wired today; dashed = present integration, optional or planned wiring.

3. Backend modules (services/hermes-tv-api/src/)

The API is a single Express app composed of seventeen route modules and seven lib modules. Every JSON response passes through credentialGuard, which wraps res.json and refuses to send if it detects a known credential shape - defence in depth against accidental leaks.

Middleware chain (order matters)

  • 1. cors - allows localhost, hermestv.local, and any LAN 192.168.x.x origin.
  • 2. express.json({ limit: '64kb' }) - bounded body parsing.
  • 3. requestLogger - logs method - path - status - ms; never the body.
  • 4. credentialGuard - wraps res.json; blocks responses that look like they contain credentials.

Seed data

data/seedCatalog.js exports SEED_CATALOG with 147 items (live channels, VOD, series, and episodes) so every layout shell renders a full grid before the operator has wired any real provider. Each item carries a providers[] array referencing the four apollo_group xtremehd iptv-org jellyfin provider IDs.

4. Frontend modules (apps/hermes-web-tv/src/)

React 18 SPA built with Vite. Targets Chrome 76 (Tizen 2020 WebView) - no optional chaining or nullish coalescing in shipped code paths. The same bundle runs in the browser and packed into a Tizen .wgt. Mom (Sherri) on the QN85 and Dave on Windows both reach the same Vite-built artifact through the host nginx.

No credentials are ever served to the client. The credentialGuard middleware blocks res.json calls whose payload matches known token shapes; provider IDs and display labels travel free.

6. Boot sequence flowchart

On every load the web app picks (or restores) a profile, then runs bootWithProfileId: it probes the API once via isReachable, picks the live or mock client, and fans out three parallel requests. If reachability fails, the offline banner appears and mockApi is used silently (a deliberate UX choice being removed in favour of an honest "Offline" mode).

Diagram 3 - Boot. Once both branches resolve the app calls applyDocumentTheme(profile) and renders the chosen shell.

7. Chatbot command flow

Voice input (Samsung mic only - no Bixby) and text input both feed the same /api/ui-command/validate endpoint. The route table has 22 regex patterns for the fast path; misses fall through to the LLM fallback. The validated action is dispatched back into the app's reducer.

Diagram 4 - Chatbot. Fast path returns in <50 ms; the LLM path is optional and disabled by default.

8. Play-ticket flow

Raw stream URLs are never returned to the client. /api/play issues a 5-minute ticket containing item + provider metadata and a stream_endpoint pointer. The actual byte-stream proxy lands in Phase 4 - today the endpoint returns 503 player_pipeline_not_implemented with the ticket payload, so the frontend wiring is testable end-to-end without a real stream.

Diagram 5 - Play. The raw stream URL never appears outside the server process; the ticket is the only artifact crossing the wire.

9. Catalog source resolution

routes/catalog.js resolves the catalog in a deterministic order and surfaces the active source to the client via the X-Catalog-Source response header. The Settings panel reads that header and renders an honest provider badge.

Diagram 6 - catalog resolution. The iptv-org merge runs on every branch when the cache is populated; the merge takes the badge to green.

10. Tizen Back-key modal-stack cascade

Samsung remote sends keyCode 10009 for Back. The app dismisses modals in priority order; only when no modal is open does Back take the user back to the profile picker (and from there an actual Tizen exit). utils/tizenKeyMap.js maps the full key set (Smart Hub, Guide, RGYB, transport keys).

Diagram 7 - Modal-stack cascade. Each Back press dismisses exactly one layer; the user is never trapped, and a Tizen-native exit only happens at the root.
